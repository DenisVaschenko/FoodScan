# Перевірка реалізації

Дата: 16 листопада 2026 року.

## Виконано

- Release-збірка API та тестового проєкту під .NET SDK 10.0.100.
- 25 автоматизованих перевірок через альтернативний in-process runner. Це ті самі xUnit-методи та InlineData-набори, що використовує `dotnet test`.
- Інтеграційні HTTP-тести через ASP.NET Core TestServer із реляційною SQLite in-memory. OCR/LLM у цих тестах замінено керованими відповідями.
- Реальне декодування й повторне кодування PNG через SkiaSharp, відхилення пошкодженого файлу та надто малого зображення.
- Реальний Tesseract 5 з українськими й англійськими мовними даними на синтетичному зображенні `samples/label-test.png`. Отриманий текст збігся з `samples/label-test.txt`:

```text
Склад: молоко, цукор.
Може містити арахіс.
```

## Що покривають тести

| Група | Перевірки |
|---|---|
| Авторизація | 401 без токена; реєстрація; хешований пароль; неправильний пароль; повторний email; профіль |
| Refresh / logout | ротація; старий токен більше не працює; відкликання refresh token |
| Дані користувачів | чужий аналіз не читається, не видаляється й не перераховується; чужі списки та історія не видимі |
| Історія | знімок налаштувань; новий запис після виправлення; пагінація; видалення |
| Валідація | порожній текст, неправильна пагінація, невідомий компонент, неправильний/відсутній reason, два файли |
| Зіставлення | молочний похідний → група; можливі сліди; апострофи; хибні схожі слова; відкидання непідтверджених інгредієнтів |
| Gemini | структура запиту; JSON-схема; API-key header; коректний JSON; квота; HTTP 500; відсутні кандидати; обрізана відповідь |
| Документація | OpenAPI генерується з працюючого застосунку |

## Не перевірено наскрізно

- **Реальний Gemini API**: ключ користувача не надано. HTTP-адаптер протестовано із заміною transport handler, але доступність конкретної моделі й квоту потрібно перевірити після налаштування `.env`.
- **Docker Compose / реальний PostgreSQL**: у середовищі створення немає Docker. PostgreSQL DDL згенеровано справжнім Npgsql EF Core provider; інтеграційні тести виконано на SQLite. Контейнери потребують першого запуску на комп'ютері користувача.
- **Якість на реальних упаковках**: синтетичний напис перевіряє роботу OCR, але не доводить точність на зігнутій, блискучій або погано освітленій упаковці.
- Навантаження, усі EXIF-орієнтації, конкурентний refresh під реальним PostgreSQL, тайм-аут зовнішнього процесу та повний словник алергенів не мають окремого наскрізного підтвердження.

Стандартний VSTest потребує міжпроцесних сокетів, недоступних у середовищі створення. Тому перевірки виконано in-process, без послаблення тестових перевірок. На звичайному ПК доступний `dotnet test FoodScan.sln -c Release`.

## Повторити локально

```powershell
dotnet build FoodScan.sln -c Release
dotnet test FoodScan.sln -c Release
# Альтернатива VSTest:
dotnet run --project tests/FoodScan.Tests -c Release -- --selftest
# Справжній OCR; Tesseract із ukr+eng має бути в PATH:
dotnet run --project tests/FoodScan.Tests -c Release -- --ocr samples/label-test.png
```

Повторення реального сценарію із Gemini: запустіть Docker Compose з ключем і моделлю та виконайте `scripts/demo.ps1 -ImagePath samples/label-test.png`.
